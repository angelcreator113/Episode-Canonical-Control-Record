# A1c R1 ("integrity"): implementation specification

**Status:** specification only. Nothing is implemented. Implementation, PR, merge and deploy each need Evoni's approval.

**Design:** `docs/reads/2026-10-27-a1c-design-audit.md`, revision 4. This spec follows its Revision 4 section first, then the revision 3 body.

**Base:** `main` `2899dbc9`.

## 1. Purpose and limits

R1 puts every script write through **one save service**. It is **identity-neutral**: no line identity is written, minted, retired or changed (R4.2).

**R1 changes these behaviours, all explicitly approved, and nothing else (condition 3):**

| # | Change | Ruling |
|---|---|---|
| C1 | Text, locks and the version row save atomically; a failed version write fails the save | N2 |
| C2 | A text write to a non-empty script needs `script_revision`. Missing → `409 SCRIPT_REVISION_REQUIRED`; stale → `409 SCRIPT_CHANGED` | D6, P2 |
| C3 | A generator whose script changed during its run returns its draft unsaved: `409 SCRIPT_CHANGED` with `draft` | N3 |
| C4 | Event inject keeps its intended beat. It refuses with `409 INJECT_BLOCKED_BY_LOCK` (naming the beat) when that beat is locked, when an old tag is in a locked beat, or when the script is headerless and a lock is in force | D9, P3 |
| C5 | Six writers gain a transaction and row lock; W5 reads inside its transaction | D10 |
| C6 | W9 gains the overwrite guard. W4 gains it too, because today it copies an `episode_scripts` row over the episode unguarded | D10 |
| C7 | W3 and W4 report a failed save instead of swallowing it | D10 |
| C8 | W6, W7 and W8 return the saved text and episode, not the raw skeleton or the pre-draft row | D10 |
| C9 | A save carrying `restored_from` is recorded as source `restore` only when its text, after lock-keeping, equals the server's copy of that version after lock-keeping. Otherwise it is recorded as an ordinary `save`. The browser's text is never taken as the version's | D5 |
| C10 | An episode whose `script_line_keys` is not null is refused: `409 LINE_IDENTITY_ACTIVE`. None is expected in production | R4.2 |

**These stay exactly as today:**
- lock-keeping (`scriptKeepingLocks`, `keepLockedBeats`), including renumbering to 15+;
- overwrite-guard semantics and confirmations;
- version sources;
- retention limits (50 / 10) and de-duplication;
- every response field that exists today. Responses only gain fields; the only corrected values are C8's;
- `script_voice_clips` and every other consumer.

## 3. Interfaces

**Request** (Save and Approve): the existing body plus `script_revision` (string).

**Responses** (additive): `script_revision`, plus the four 409 bodies:

| Code | Body |
|---|---|
| `SCRIPT_REVISION_REQUIRED` | `{ code, message, current_revision }` |
| `SCRIPT_CHANGED` | `{ code, message, current_revision, draft? }`. `draft` is present only on generator conflicts (C3): the unsaved generated text |
| `INJECT_BLOCKED_BY_LOCK` | `{ code, message, beat_number, beat_label, reason: 'intended_beat_locked' \| 'old_tag_in_locked_beat' \| 'headerless_locked' }` |
| `LINE_IDENTITY_ACTIVE` | `{ code, message }` |

## 4. Acceptance tests

### 4.1 Integration, per writer (Postgres)

Each of W1–W10 is tested for:

| Check | Expected |
|---|---|
| a | it writes the same text as today for the same input: lock-keeping parity on fixtures with locked beats and extras |
| b | text, locks and the version row commit together, and **a forced version-row failure leaves all three unchanged** (C1) |
| c | a non-null `script_line_keys` → `409 LINE_IDENTITY_ACTIVE`, nothing written (C10) |
| d | `script_line_keys` is still `NULL` on the episode and on every version row afterwards (R4.2) |
| e | `script_voice_clips` rows are identical before and after (R4.8) |
| f | a concurrent write is serialised by the row lock |

Writer-specific checks:
- **W1:** missing token on a non-empty script → `SCRIPT_REVISION_REQUIRED`; a stale token → `SCRIPT_CHANGED`; an empty script saves without a token; a title-only update needs no token; C9 records `restore` only when the texts are equal.
- **W2:** lock-only needs a token too.
- **W3 and W10:** a change during generation → `409` with `draft`, nothing saved; the `EpisodeScript` row is kept (W3).
- **W4 and W9:** guard 409.
- **W5:** each C4 refusal names its beat; a successful inject keeps the intended beat and its links.
- **W6, W7 and W8:** the response carries the saved text.

### 4.2 Unit

- `scriptRevision` properties.
- The strict mode, including the `[Yes., Hello, Yes.]` → `[Yes., Yes., Hello]` case (uncertain) and a pure deletion (kept).
- The A1a suite unchanged.
- The identity-plan log is counts only and safe on failure.
- `IDENTITY_WRITES === false`.

### 4.3 Static guards

1. Only `scriptSave.js` writes `script_content` or `script_line_keys`. That covers `update`, `save`, assignment, `Episode.update` and raw SQL across `src/` and `scripts/`. Migrations, tests and create-only seeds are allowed.
2. No file but `scriptSave.js` calls `snapshotScript`.
3. The version-reference allowlist (R4.5, item 7).
4. No R1 code path includes `script_line_keys` in a write.

### 4.4 Frontend

- Save and Approve send the token.
- Each 409 shows its message and keeps the page text and the draft.
- "Load the newer script" leads to "Put them back".

### 4.5 Repository checks

`/validate` and the full Jest and Vitest suites pass.

## 5. Rollout

1. **Before the PR:** Evoni approves this spec.
2. **PR:** one PR, CI green, review. Evoni approves the merge.
3. **Pre-deploy checks** (Evoni, read-only):
   - `SELECT count(*) FROM episodes WHERE script_line_keys IS NOT NULL;` should be 0;
   - `SELECT count(*) FROM episode_script_versions WHERE script_line_keys IS NOT NULL;` should be 0;
   - plus the usual checklist. No migration is pending from R1.
4. **Deploy:** the Deploy workflow, one run. Migrate reports nothing pending, then deploy, then restart.
5. **Post-deploy checks** (Evoni):
   - **Normal save:** open the Script tab, make an edit and Save. It succeeds, and a version row appears.
   - **Stale tab:** a tab opened before the deploy gets "Save failed" on Save. After a reload it offers "Put them back".
   - **Logs:** the API log shows `[line-identity-plan]` lines with counts only.
   - **Identity untouched:** `script_line_keys` is still null everywhere.
   - **Voice clips:** none changed.

## 6. Rollback

Deploy the commit before R1 through the Deploy workflow. Nothing is pending to migrate.
- **Comes back:** the old behaviour, including the fixed bugs (C4–C8 and non-atomic history).
- **Left behind:**
  - the version rows R1 wrote, which are ordinary rows with keys null;
  - tabs opened under R1, which keep sending `script_revision`; the old server ignores it.
- **No identity data exists, so none needs cleaning up.**

## 7. Not in R1

These come later, each with its own approval:

- hints, review, recorded operations and identity writes (R3);
- the retention provider registry, which arrives with the first feature that adds a durable reference;
- voice clips (A1d, after R3).
